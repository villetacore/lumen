# Спецификация формата Lumen

Версия: `0.1`. Обязательна к реализации и в Go (`server/internal/markdown`),
и в Rust (`desktop/core/src/md`). Обе реализации проходят одни и те же
golden-тесты из [`testdata/`](testdata).

## 1. Заметка

Файл `*.md` в UTF-8, LF или CRLF. Опциональный YAML frontmatter в начале файла:

```markdown
---
id: 01K5Q9V3JX8ZQ2N6C1B7M4TDA0
title: Запуск Lumen
type: project
tags: [work, lumen]
created: 2026-09-08T10:00:00+03:00
updated: 2026-09-08T12:31:11+03:00
status: active
---

# Запуск Lumen

- [ ] Написать спецификацию формата [due:: 2026-09-10] ^k5q9v3
```

### Поля frontmatter

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | ULID (26 симв.) | нет¹ | Стабильный идентификатор заметки |
| `title` | string | нет² | Заголовок |
| `type` | `note`\|`project`\|`area`\|`daily`\|`meeting`\|`event`\|`issue`\|`sprint` | нет | Влияет на представления; `issue`/`sprint` — §7 |
| `tags` | string[] | нет | Теги (без `#`) |
| `created` / `updated` | RFC3339 | нет | Времена |
| `status` | string | нет | Для `type: project` |
| `start` / `end` | RFC3339 или `YYYY-MM-DD` | нет | Делает заметку событием календаря |
| `allday` | bool | нет | Событие на весь день |
| `aliases` | string[] | нет | Доп. имена для `[[ссылок]]` |
| `source` | object | нет | Метка интеграции: `{connector, external_id, url}` |

¹ Если `id` нет, идентификатор заметки — её путь относительно корня vault.
`id` проставляется лениво, при первой записи в файл через API.
² Если `title` нет — берётся первый `# H1`, иначе имя файла без расширения.

Неизвестные поля frontmatter **сохраняются как есть** при записи.

## 2. Задача

Задача — строка-чекбокс в любой заметке, на любом уровне вложенности списка:

```
- [ ] Текст задачи #tag [due:: 2026-09-10] [prio:: A] ^blk1a2b
```

### Статусы

| Символ | Статус | Смысл |
|---|---|---|
| ` ` | `todo` | Не начата |
| `/` | `doing` | В работе |
| `x`, `X` | `done` | Выполнена |
| `-` | `cancelled` | Отменена |
| `>` | `deferred` | Перенесена |

Любой другой символ в скобках → статус `todo`, символ сохраняется при записи.

### Инлайн-поля

Синтаксис `[ключ:: значение]` (совместим с Dataview).

| Ключ | Значение | Пример |
|---|---|---|
| `due` | дата | `[due:: 2026-09-10]` |
| `scheduled` | дата | `[scheduled:: 2026-09-09]` |
| `start` | дата | `[start:: 2026-09-08]` |
| `done` | дата | `[done:: 2026-09-08]` |
| `prio` | `A`\|`B`\|`C`\|`D` | `[prio:: A]` |
| `est` | длительность | `[est:: 2h30m]` |
| `project` | wikilink или текст | `[project:: [[Запуск Lumen]]]` |
| `repeat` | RRULE-lite | `[repeat:: every week]` |
| `assignee` | текст | `[assignee:: alex]` |

Дата: `YYYY-MM-DD` либо `YYYY-MM-DDTHH:MM`. Относительные значения
(`today`, `tomorrow`, `завтра`, `+3d`) принимаются **на входе от UI** и
нормализуются в абсолютную дату перед записью в файл.

### Идентичность задачи

1. Если строка заканчивается на `^blockid` — это идентификатор задачи.
2. Иначе идентификатор вычисляемый и **нестабильный**:
   `sha1(relpath + "\n" + normalizedText)[:12]`, при коллизии добавляется порядковый номер.
3. При первой записи в задачу через API ей присваивается `^blockid`
   (6 символов base32 от ULID) — так ссылки становятся стабильными.

`blockid`: `^[a-z0-9]{3,32}$`, в конце строки, отделён пробелом.

### Вложенность

Задачи наследуют «родителя» по отступу списка. Родительская задача не считается
выполненной автоматически.

## 3. Ссылки и теги

- `[[Заметка]]`, `[[Заметка|алиас]]`, `[[Заметка#Заголовок]]`, `[[Заметка#^blockid]]`.
- Разрешение имени: точное совпадение `id` → путь → имя файла → `aliases`.
- `#tag`, `#вложенный/тег`. Не считается тегом внутри кода (`` ` ``), ссылок и `#` в начале строки (заголовок).

## 4. События календаря

Источники событий для календаря:
1. Frontmatter `start`/`end` в заметке (`type: event` или любой другой).
2. Задачи с `due` или `scheduled`.
3. Ежедневная заметка по имени файла `YYYY-MM-DD.md`.
4. Внешние ICS-подписки (не файлы, живут только в индексе).

## 5. Раскладка vault (соглашение, не требование)

```
vault/
├── 00-inbox/
├── 10-notes/
├── 20-projects/
├── 30-areas/
├── 40-daily/2026/2026-09-08.md
├── 50-meetings/
├── 90-archive/
├── _templates/
└── .lumen/
    ├── config.yaml      настройки vault (папка дневников, шаблоны, представления)
    └── cache/           индекс, не синхронизируется
```

Файлы и папки, начинающиеся с `.`, а также `.lumen/cache/`, из индекса исключены.

## 6. Правила записи (lossless)

- Изменение задачи затрагивает **только её строку**.
- Изменение frontmatter сохраняет порядок ключей и неизвестные поля.
- Не меняются: перенос строк (LF/CRLF определяется по файлу), финальный перевод строки,
  отступы, стиль маркеров списка.
- Запись атомарна: `tmp` в той же директории → `fsync` → `rename`.

## 7. Трекер: проект, тикет, спринт

Вложенность проектов и страниц — см. [§8](#8-деревья-проектов-и-страниц).

Принято в [ADR-0010](../docs/adr/0010-issue-files.md). Это обычные заметки: десктоп
(Rust) читает их как заметки с frontmatter и задачами §2; семантику трекера
реализует только сервер (Go). Golden-фикстуры: `testdata/tracker-*.md`.

### Проект трекера

Заметка `type: project` с полем `key` — 1–10 заглавных латинских букв или цифр,
первая — буква (`WEB`, `LUM2`). Без `key` проект остаётся обычным.

| Поле | Тип | Описание |
|---|---|---|
| `key` | string | Префикс ключей тикетов |
| `workflow` | список `{id, name, category, wip?}` | Колонки по порядку; `category`: `todo`\|`in_progress`\|`done`. По умолчанию `todo`, `in-progress`, `done` |
| `transitions` | map `статус → [статусы]` | Разрешённые переходы; нет поля или статуса в нём — переход свободный |
| `issue_types` | list | По умолчанию `task, bug, story, epic`; первый — тип по умолчанию |
| `issue_seq` | int | Последний выданный номер; номера удалённых тикетов не переиспользуются |

### Тикет

Файл `<папка проекта>/<KEY>/issues/<KEY>-<N>.md` (место создания; при чтении
путь не важен — тикет находится по `type` и `id`).

```markdown
---
id: WEB-12
title: Канбан-доска проекта
type: issue
project: WEB
issue_type: story
status: in-progress
priority: high
assignee: alice
reporter: bob
watchers: [carol]
labels: [web]
epic: WEB-1
parent: WEB-10
sprint: WEB-S3
start: 2026-11-03
due: 2026-11-10
estimate: 1d
points: 3
rank: i
links:
  - blocks: WEB-14
  - relates: [WEB-2, WEB-3]
created: 2026-11-02T10:00:00Z
updated: 2026-11-02T12:30:00Z
---

Описание (Markdown). Задачи §2 до раздела комментариев — чек-лист тикета.

## Комментарии

### 2026-11-02 12:30 · alice ^c-7f3a
Текст комментария.
```

- `id` — ключ тикета; без него ключом считается имя файла. Ссылка `[[WEB-12]]`
  разрешается по `id`, поэтому смена заголовка её не ломает.
- `project` — ключ проекта; без него берётся префикс ключа.
- `status` — `id` колонки workflow; без поля — `todo`. `issue_type` без поля — `task`.
- `assignee`, `reporter`, `watchers` — имена пользователей (`preferred_username` OIDC).
- `rank` — дробный ранг на алфавите `0-9a-z`: порядок на доске — по возрастанию
  `rank`, тикеты без ранга — в конце по номеру. Перестановка переписывает `rank`
  только у перемещённого тикета.
- Раздел `## Комментарии` (или `## Comments`) идёт последним; каждый комментарий —
  заголовок `### <YYYY-MM-DD HH:MM> · <автор> ^c-<id>` и текст до следующего
  заголовка. Заголовки внутри fenced-блоков не считаются.
- Неизвестные поля frontmatter сохраняются; запись одного поля меняет только строки
  этого ключа (вместе с его вложенными строками).

### Спринт

Файл `<папка проекта>/<KEY>/sprints/<KEY>-S<N>.md`, `type: sprint`.
Golden-фикстура: `testdata/tracker-sprint.md`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | `WEB-S3`; без поля — имя файла. Номера не переиспользуются |
| `title` | string | Название («Спринт 3») |
| `project` | string | Ключ проекта; без поля — префикс `id` |
| `state` | `planned`\|`active`\|`closed` | По умолчанию `planned`. В проекте не больше одного `active` |
| `goal` | string | Цель спринта |
| `start`, `end` | date | Даты; как у любой заметки §1, спринт с датами виден в календаре |
| `completed` | date | Когда спринт закрыт |

Тикет входит в спринт полем `sprint: WEB-S3`. Бэклог — открытые тикеты без
спринта (или со спринтом, которого нет среди открытых). При закрытии спринта
незавершённые тикеты (категория статуса не `done`) переносятся в бэклог или в
запланированный спринт того же проекта; завершённые сохраняют `sprint` для
отчётов. Закрытый спринт не принимает тикеты.

## 8. Деревья проектов и страниц

Дерево записано в ключах frontmatter. Файлы при перемещении не меняют путь, поэтому
ссылки `[[…]]` и пути остаются рабочими ([ADR-0020](../docs/adr/0020-trees-and-automations.md)).

**Подпроект.** Заметка проекта с ключом `parent_project: <KEY>`. Цикл или неизвестный
родитель, записанные вручную, не ошибка чтения: проект показывается верхним уровнем.

**Страница.** Заметка с `content_kind: document`:

| Ключ | Значение |
|---|---|
| `parent` | `note:<id>` родителя: страницы, проекта или тикета; `task:<id>` задачи; нет ключа — верхний уровень |
| `rank` | Дробный ранг среди соседей, как у тикета. Страницы без ранга идут после ранжированных, по названию |

Подзадача — тикет с `parent: <KEY>` тикета того же проекта (поле описано в §7).
Автоматизации в файлах не хранятся: это настройка в операционной БД.
