# Участие в Lumen

Спасибо за интерес к проекту. Исправления, воспроизводимые баг-репорты и улучшения
документации полезны наравне с новыми возможностями.

## Баги и предложения

Создайте [issue](https://github.com/villetacore/lumen/issues) с версией или SHA,
способом запуска, шагами, ожидаемым и фактическим результатом. Для ошибки данных
приложите небольшой обезличенный Markdown-пример. Не прикладывайте свой vault,
токены, cookies или содержимое менеджера паролей. Уязвимости обсуждаются по
[политике безопасности](SECURITY.md).

Для большой функции сначала опишите сценарий и границы в issue. Сверьтесь с
[направлением продукта](docs/plans/PRODUCT_DIRECTION.md) и
[backlog](docs/plans/BACKLOG.md), чтобы не дублировать работу.

## Локальный цикл

1. Создайте fork и ветку для одной задачи.
2. Настройте окружение по [руководству разработчика](docs/DEVELOPMENT.md).
3. Внесите изменение, сохранив совместимость Markdown и API.
4. Выполните относящиеся проверки; для backend/web команды приведены ниже.
5. Откройте pull request в `main`: проблема, новое поведение, проверка,
   ограничения и миграция, если она требуется. Для UI приложите скриншоты.

```bash
(cd server && go vet ./... && go test -race ./...)
(cd web && npm run typecheck && npm test && npm run build)
git diff --check
```

Go форматируется `gofmt`; TypeScript следует существующему стилю. Не добавляйте
сгенерированные сборки, локальные vault, секреты или закрытый конфиг выкатки.
Для правок только Markdown достаточно проверить факты, команды, ссылки и diff.

## Версии

Каждый коммит в `main` после зелёных проверок получает следующую patch-версию (SemVer):
git-тег, образ и GitHub Release создаёт CI. Minor и major выпускают мейнтейнеры тегом
`vX.Y.Z`, как описано в [DEPLOY](docs/DEPLOY.md#версии-и-релизы).
В pull request номер версии менять не нужно. Заметки релиза собираются из заголовков
PR, поэтому заголовок должен понятно описывать изменение.

## Границы проекта

- Рабочий стек — существующий модульный Go-сервер и React-клиент. Desktop
  меняется отдельной согласованной задачей.
- Markdown — источник локального контента; внешний сервис владеет своим объектом.
- Изменения редактора должны сохранять draft при refetch, конфликте и уходе.
- Для импортов проверяйте повтор, частичный сбой и восстановление после рестарта.
- Не заменяйте принятый ADR молча: опишите новое решение и миграцию.
- Реальные внешние записи и деплой не являются частью обычного тестирования.

[AGENTS.md](AGENTS.md) задаёт дополнительные инструкции для AI-агентов.
Фактическое выполнение LUM-задач фиксируется в [PROGRESS](docs/plans/PROGRESS.md),
а незавершённая приёмка остаётся `partial`.

Вклад принимается на условиях [MIT](LICENSE). Сохраняйте лицензии сторонних
ассетов и указывайте происхождение добавляемых материалов.
