# Решение проблем

| Симптом | Что проверить |
|---|---|
| `/` показывает заглушку вместо приложения | Выполните `npm ci --prefix web`, затем `make app`. Простой `go run` не собирает UI. |
| Dev-сервер Next открывается, но API недоступен | Запущен ли backend на `127.0.0.1:8787`; верен ли `LUMEN_API`; свободен ли порт. |
| `401` или `403` | Токен, параметры OIDC, роли/группы и время на сервере. Не отключайте авторизацию для обхода ошибки. |
| После перезапуска требуется войти снова | OIDC-сессии находятся в памяти процесса; выполните повторный вход. |
| Календарь пуст после рестарта | Дождитесь первой проверки подключений (до 30 секунд), проверьте источник и ошибку подключения. События не сохраняются как offline snapshot. |
| Импорт перестал обновляться | Проверьте ошибку подключения: правка внутри блока источника вызывает конфликт. Сначала сохраните локальный текст; не удаляйте state наугад. |
| Изменения заметки конфликтуют | Скопируйте draft, сравните версию на диске и выберите вариант сохранения в редакторе. |
| Нет прав записи в контейнере | Том `/vault` должен быть доступен UID 65532; проверьте владельца и режим доступа. |
| Bitwarden/KeePass не работает в образе | Стандартный distroless-образ не включает `bw` и `keepassxc-cli`. Используйте поддерживаемый источник секрета `env:`/`file:`. |
| Старый интерфейс после выкатки | Сверьте SHA запущенного образа, завершение rollout и обновите вкладку. Один успешный push не означает завершённую выкатку. |

`GET /healthz` позволяет проверить доступность процесса без чтения данных.
`lumend version` показывает версию бинарника. Логи запуска и ошибки подключения
помогают отличить ошибку Lumen от недоступности внешнего сервиса.

Если проблема повторяется, создайте [issue](https://github.com/villetacore/lumen/issues)
с версией, способом запуска и минимальным обезличенным примером. Уберите токены,
cookies, внутренние URL и персональные данные из логов и скриншотов.

См. [эксплуатацию](OPERATIONS.md), [авторизацию](AUTH.md) и
[правила участия](../CONTRIBUTING.md).
