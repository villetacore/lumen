# Пароли: чтение из Bitwarden, Vaultwarden и KeePass

Раздел **Пароли** показывает записи из вашего менеджера паролей прямо в Lumen —
в вебе и в десктопном приложении. Это клиент к чужому хранилищу, а не ещё одно
хранилище.

## Что Lumen делает и чего не делает

**Делает:** открывает хранилище по мастер-паролю, показывает список записей,
ищет по нему и по запросу отдаёт одно поле одной записи.

**Не делает:**

- не пишет в вашу базу — доступ только на чтение;
- не сохраняет мастер-пароль: он нужен один раз, чтобы получить сессию;
- не кладёт пароли в vault, в индекс, в поиск и в резервные копии;
- не пишет значения в логи;
- не хранит открытые значения на диске — сессия живёт только в памяти процесса
  и исчезает при перезапуске.

Файл настроек `.lumen/passwords.yaml` содержит только пути и ссылки:

```yaml
stores:
    - id: lichnoe
      kind: keepass
      name: Личное
      values:
        db: D:/keys/personal.kdbx
        cli: C:/Program Files/KeePassXC/keepassxc-cli.exe
```

## Bitwarden и Vaultwarden

Нужен официальный `bw` CLI. Vaultwarden — совместимый сервер, ему достаточно
один раз указать адрес:

```bash
npm install -g @bitwarden/cli
bw config server https://vault.example.com   # только для self-hosted
bw login
```

Дальше в интерфейсе: **Пароли → Подключить → Bitwarden / Vaultwarden**.
Мастер-пароль вводится в Lumen, уходит в `bw unlock` **через переменную
окружения** (не через аргументы процесса, которые видны всей системе), а обратно
приходит сессия — её Lumen и держит.

Если сессию удобнее готовить снаружи, заполните поле «Готовая сессия» ссылкой
`env:BW_SESSION`: тогда мастер-пароль вообще не спрашивается.

| Поле | Смысл |
|---|---|
| Путь к `bw` | Если бинарник не в PATH |
| Готовая сессия | Ссылка на секрет с `BW_SESSION` |
| Адрес сервера | Справочно; реально адрес задаёт `bw config server` |

## KeePass

Нужен `keepassxc-cli` — он входит в KeePassXC. Своего разбора `.kdbx` у Lumen
нет намеренно, см. [ADR-0007](adr/0007-secret-references.md).

**Пароли → Подключить → KeePass (KeePassXC)**:

| Поле | Смысл |
|---|---|
| Файл базы | Путь к `.kdbx` |
| Файл-ключ | Если база открывается ключом |
| Только файл-ключ | База без пароля |
| Путь к `keepassxc-cli` | На Windows обычно `C:\Program Files\KeePassXC\keepassxc-cli.exe` |

Пароль базы передаётся утилите через stdin и остаётся в памяти сервера: у
`keepassxc-cli` нет сессии, поэтому каждый следующий вызов предъявляет его
заново.

## Автозакрытие

Открытое хранилище закрывается само после 15 минут без обращений. Время до
закрытия видно рядом с названием. Кнопки «Закрыть» и «Закрыть все» делают это
немедленно; перезапуск сервера закрывает всё.

## Показ и копирование

Значение запрашивается только по нажатию «Показать» или «Копировать» — до этого
оно не покидает менеджер паролей. Скопированное стирается из буфера обмена через
30 секунд.

Ответ на запрос значения отдаётся с `Cache-Control: no-store` и приходит на
`POST`, а не `GET`: идентификатор записи не должен попасть ни в URL, ни в логи
прокси.

## Доступ

Эндпоинты паролей закрыты той же аутентификацией, что и остальной API. Кроме
того, они **отказываются работать**, если сервер слушает не только localhost и
при этом не требует входа:

```
доступ к паролям запрещён: сервер слушает не только localhost
и не требует входа. Включите --oidc-issuer или --token
```

Остальной API — это ваши заметки; этот раздел — чужое хранилище паролей, и
случайно открыть его в сеть нельзя.

## Модель угроз

Защищает от: случайного попадания паролей в заметки, git и бэкапы; от того,
что кто-то откроет Lumen в сети и увидит хранилище.

**Не защищает** от того, кто уже получил доступ к работающему серверу или к
вашей сессии в браузере: пока хранилище открыто, значения доступны через API.
Поэтому автозакрытие короткое, а на сетевом сервере обязателен вход.
