# План frontend

Статус: предложение для существующего React-клиента. Flutter не меняется.

## Информационная структура

| Раздел | Основной сценарий |
|---|---|
| Обзор | Мои задачи, встречи, недавние документы и операции, требующие внимания |
| Проекты | Контекст проекта: заметки, внешние задачи, встречи, ссылки и действия |
| Знания | Дерево/список документов, поиск, источники, редактор и обратные ссылки |
| Задачи и календарь | Существующие экраны, явные источник и состояние синхронизации |
| Помощник | Диалог, выбранные источники, цитаты, подготовленные действия |
| Поручения | Запуски агентов, ход работы, результаты, остановка и очередь решений |
| Сценарии | Версионируемые процедуры студии, входные данные, ручной запуск и расписание |
| Подключения | Каталог возможностей, настройка, проверка доступа и история заданий |
| Настройки | Права, модели, MCP, размещение данных; пароли остаются отдельной областью |

Первый вертикальный сценарий: проект → связанный issue → preview закрытия →
выполнение → результат в источнике. Второй: поиск инструкции → просмотр документа
и источника → вопрос помощнику → проверяемая цитата. Эти сценарии важнее полной
перерисовки всех существующих страниц.

Дополнение для студии: после первого сценария действий сделать экран поручения
«Сводка проекта» до полного RAG. Главная страница показывает результаты агентов
и требующие решения операции. В проекте доступны Sessions, Artifacts и Playbooks
как вкладки контекста; не обязательно добавлять отдельный верхнеуровневый раздел
на каждую внутреннюю сущность. Детали — [runtime](AGENT_RUNTIME.md).

## Переиспользуемые части

Сохранить React Router и TanStack Query. Разделять код по features, постепенно
выделить компоненты карточки ресурса, source badge, freshness, списка заданий,
diff/approval, ошибки запроса и empty state. Единые tokens цветов/отступов и
компоненты форм нужны до новых экранов; новая state-библиотека сама по себе не нужна.

API-клиент генерировать из согласованного OpenAPI. Query keys включают workspace
и фильтры. SSE инвалидирует затронутые сущности, а после пропуска событий выполняется
управляемый refetch. Смена пользователя очищает защищённый кэш.

## Редактор и сохранность работы

Сначала устранить сброс несохранённого `draft` при изменении `note.revision` в
`NotePage.tsx`. Хранить base revision отдельно от последней серверной версии.
Внешнее обновление во время редактирования показывает конфликт, а не заменяет текст.
Переход со страницы предупреждает о несохранённой работе. Локальное хранение
черновиков — отдельная настройка с учётом чувствительности данных.

После этого добавить CodeMirror, Markdown preview с безопасным рендерингом,
wikilinks, переход к заголовку/цитате, keyboard navigation. `409` предлагает diff,
повторное применение или копирование своего текста; произвольная ошибка не должна
выдаваться за конфликт версии. Удалённая заметка не уничтожает открытый draft.

## Интеграции и действия

У подключения видны последние успешное чтение и ошибка, следующий запуск, lag,
scopes и доступные операции. «Проверить подключение» отделено от полного импорта.
OAuth и secret references показываются как отдельные способы настройки без вывода
значений токенов. После отключения объясняется судьба локальных заметок и проекций.

У внешней карточки — название сервиса, canonical URL, свежесть, права и состояние.
Для действия показываются объект и конкретное изменение. `queued`, `running`,
`unknown`, `conflict` отображаются раздельно; таймаут не выдаётся за неуспех, который
можно бездумно повторить. Историю можно открыть по action ID.

## Поиск и помощник

Одна строка поиска с фильтрами по проекту, источнику, типу и времени. Результаты
показывают фрагмент, источник, время и переход к оригиналу. Ответ AI размещается
рядом с найденными источниками; обычный поиск доступен и без модели.

В диалоге пользователь видит область поиска, модель, ссылки на источники и кнопку
остановки. Предложение изменить сервис показывается отдельной карточкой действия.
Ошибки провайдера и отсутствие подтверждающих документов различаются. Не показывать
скрытые рассуждения модели: достаточно статуса чтения источников и действий.

## Проверка UX

E2E покрывают: сохранение draft при SSE, конфликт версии, подключение и ошибку
источника, один внешний action, поиск и доступ по ролям, ответ с цитатой, отмену
генерации. Проверить клавиатуру, focus в модальных окнах, labels, контраст,
узкую ширину, длинные названия, loading/error/empty/stale состояния.
Макеты сначала для двух вертикальных сценариев; визуальный редизайн остальных
экранов не должен блокировать исправление потери данных.
