# Трекер задач и база знаний поверх Markdown

Дата: 2026-11-02. Статус: **план**, функции ниже не реализованы.
Запрос владельца: Lumen должен работать как нормальный таск-трекер (уровня Jira)
и база знаний (уровня Confluence): канбан, спринты, диаграммы, работа команды,
страницы. Основа — Markdown и календарь; интеграция с Nextcloud (файлы и календарь).

Решения владельца от 2026-11-02:

| Вопрос | Решение |
|---|---|
| Хранение тикетов | Один `.md` файл на тикет с frontmatter; чекбоксы в заметках остаются лёгкими подзадачами |
| Пользователи | Команда через Keycloak/OIDC: исполнители, наблюдатели, @упоминания, права на проекты и пространства |
| Диаграммы | Mermaid в страницах, диаграмма Ганта, отчёты по задачам, рисунки Excalidraw |
| Nextcloud | Vault (или его часть) синхронизируется с папкой Nextcloud Files по WebDAV; календарь — CalDAV с записью |

Этот трек идёт **раньше** агентных срезов D–G: агенты позже работают поверх тех же
тикетов, страниц и прав. Существующие ограничения AGENTS.md сохраняются: Go/React,
модульный монолит, desktop не меняем, внешние записи — только на тестовых сервисах.

## Модель данных

### Проект и тикет

Проект — папка с файлом настроек; тикет — отдельный файл с устойчивым ключом.
Имя файла не зависит от заголовка, поэтому переименование тикета не ломает ссылки.

```text
vault/20-projects/
├── web.md                     type: project, key: WEB, workflow, типы, участники
└── WEB/
    ├── issues/WEB-12.md       type: issue
    ├── sprints/WEB-S3.md      type: sprint, start/end/goal
    └── docs/…                 страницы проекта (база знаний)
```

Точный формат — [`spec/FORMAT.md` §7](../../spec/FORMAT.md#7-трекер-проект-тикет-спринт);
пример ниже иллюстративный.

```markdown
---
id: WEB-12
type: issue
title: Канбан-доска проекта
issue_type: story          # task | bug | story | epic
status: in-progress        # id колонки из workflow проекта
priority: high
assignee: alice            # preferred_username из OIDC
reporter: bob
watchers: [carol]
labels: [web]
epic: WEB-1
parent:                    # для подзадачи-тикета
sprint: WEB-S3
start: 2026-11-03
due: 2026-11-10
estimate: 1d
points: 3
rank: i                    # дробный ранг: перестановка меняет один файл
links:
  - blocks: WEB-14
created: 2026-11-02T10:00:00Z
updated: 2026-11-02T12:30:00Z
---
Описание в Markdown, в том числе ```mermaid и ![[схема.excalidraw]].

## Чек-лист
- [ ] обычные задачи Lumen (существующий формат, видны в «Задачах»)

## Комментарии
### 2026-11-02 12:30 · alice ^c-7f3a
Текст комментария, @bob.
```

Заметка проекта (`type: project` с `key`) задаёт workflow — упорядоченные статусы с категориями
`todo | in_progress | done` (категория связывает тикет со старыми фильтрами
«открыто/выполнено»), допустимые переходы (по умолчанию любые), типы тикетов,
WIP-лимиты колонок и группы OIDC с ролями в проекте. Ключи тикетов выдаются
сервером под блокировкой проекта; следующий номер вычисляется по файлам при
старте, поэтому потеря индекса не приводит к повтору ключа.

### Где что хранится

| Данные | Источник правды | Почему |
|---|---|---|
| Тикеты, проекты, спринты, страницы, комментарии | Markdown в vault | ADR-0001: читается в Obsidian/git, переживает потерю БД |
| Рисунки | `*.excalidraw` (JSON) рядом со страницей | Обычный файл, совместим с плагином Excalidraw |
| Пользователи, группы, членство, уведомления | Операционное хранилище (LUM-010) | Приходят из OIDC, не являются контентом |
| История изменений тикета, версии страниц | Операционное хранилище, обязательный бэкап | Нужны отчётам (burndown); файл хранит только текущее состояние |
| Поиск, доска, агрегаты отчётов | Перестраиваемый индекс | Восстанавливается из файлов |

История — это журнал событий: кто, когда, какое поле, старое/новое значение.
Правка файла вне Lumen (Obsidian, git, Nextcloud) фиксируется как изменение
«вне Lumen» по diff frontmatter. Потеря журнала не теряет тикеты, но обрывает
отчёты — поэтому журнал входит в бэкап, а не в удаляемый кэш (LUM-006).

Desktop/Rust: тикет и страница остаются обычными заметками с frontmatter, чекбоксы
внутри разбираются как раньше. Семантика тикета реализуется только в Go; это
уточнение ADR-0004 фиксируется в ADR-0010 и `spec/FORMAT.md`.

### База знаний

Пространство — папка (`30-areas/<Space>/` или `docs/` проекта) с `space.md`.
Дерево страниц = папки + `parent`/`order` во frontmatter; у раздела — `_index.md`.
Шаблоны — `_templates/`. Связи страница ↔ тикет — через `[[WEB-12]]` и backlinks;
блок ```lumen-issues``` с запросом встраивает живой список тикетов на страницу.
Версии страниц сохраняются при каждом сохранении из Lumen (и при обнаружении
внешней правки), с diff и восстановлением.

## Интерфейс

| Экран | Содержание |
|---|---|
| Проекты | Список, создание проекта с ключом, настройки workflow и участников |
| Доска | Колонки по workflow, drag & drop (статус + rank), swimlanes по исполнителю/эпику, WIP, быстрые фильтры |
| Бэклог и спринты | Ранжированный бэклог, планирование, старт/закрытие спринта, перенос незакрытых |
| Список | Фильтры (статус, исполнитель, метки, спринт, срок), сохранённые фильтры, групповые действия |
| Карточка тикета | Описание (редактор LUM-026), свойства, подзадачи, связи, комментарии, история, вложения |
| Мои задачи | Назначенные, упоминания, наблюдаемые; уведомления в приложении |
| Таймлайн | Гант по `start/due`, перетаскивание сроков, зависимости `blocks`, эпики |
| Отчёты | Распределение по статусам/исполнителям, burndown спринта, cumulative flow |
| Календарь | Встречи CalDAV, сроки тикетов, спринты; перенос срока перетаскиванием |
| База знаний | Пространства, дерево страниц, хлебные крошки, шаблоны, версии, Mermaid, Excalidraw |

Дизайн — Velessoft UI (как текущий web). Draft-защита LUM-003 распространяется на
описание тикета, комментарий и страницу.

## Nextcloud

**Файлы.** Папка Nextcloud Files подключается как удалённая копия vault (или его
поддерева, например пространства базы знаний). `lumend` работает с локальной
рабочей копией, а коннектор WebDAV двусторонне синхронизирует её: PROPFIND с
ETag/`getlastmodified` для изменений, PUT с `If-Match`, удаление — в корзину Lumen.
Конфликт по ADR-0002: обе версии сохраняются, пользователь видит конфликт.
Монтирование WebDAV как файловой системы отклонено: нет атомарного rename,
watcher и fsync ненадёжны. Детали — в ADR (LUM-079) до реализации.

**Документы Office.** Произвольные файлы Nextcloud (docx, xlsx, pdf) прикрепляются
к тикету или странице ссылкой с превью и кнопкой «Открыть в Nextcloud».

**Календарь.** Существующий CalDAV-коннектор получает запись: создание, перенос и
удаление события с `If-Match`, обработкой 412 и неизвестного исхода. Сроки тикетов
и спринты могут публиковаться в выбранный календарь. Записи проверяются только на
тестовом экземпляре (Radicale или тестовый Nextcloud в docker), не на боевом.

## Зависимости от существующего плана

Командный режим требует LUM-010 (операционное хранилище), LUM-012 (policy) и
LUM-015 (сетевой auth/CSRF). Однопользовательские части трека (формат, доска,
спринты, Mermaid, дерево страниц) от них не зависят и начинаются сразу.
Запись в CalDAV/WebDAV использует jobs/outbox LUM-013, чтобы повтор и рестарт не
дублировали изменения.

## Не входит

Собственный CRDT/совместное редактирование в реальном времени (ADR-0002 остаётся),
конструктор workflow со скриптами, учёт времени и биллинг, импорт из Jira/Confluence
(можно позже), мобильное приложение, изменения desktop.
