# Обзор инфраструктуры и архитектуры

Дата: 2026-11-04. Источники: код Lumen, манифесты `homelab` (`k8s/apps/lumen`,
коммит 5dc54e5, локальная копия), его runbook'и, публичные `/healthz` и `/api/v1/me`.
В кластер и на серверы не заходил: состояние подов, PVC и бэкапов здесь по
документам, а не по факту. Проверить стоит пункты с пометкой «уточнить».

## Как устроено сейчас

```
GitHub villetacore/lumen → CI: тесты, образ ghcr.io/villetacore/lumen:<sha12>
  → зеркало в GitLab (раз в 5 минут) → MR с тегом в homelab, сливается сам
  → Argo CD (autoSync) → k3s, namespace lumen, один под, стратегия Recreate
       /vault  — PVC lumen-store, local-path, узел k3s-2, 2 ГБ
       /state  — PVC lumen-state, local-path, узел k3s-2, 1 ГБ
       вход    — Keycloak, realm velesoft, публичный клиент lumen с PKCE
```

Основа хорошая: один процесс, неизменяемые образы, GitOps с откатом через revert,
секреты в SOPS, непривилегированный контейнер с read-only корнем. Менять схему или
дробить монолит причин нет. CT 141 из старой схемы удалён 02.11.

## Что нужно в homelab для новых возможностей

Изменения **не применены**: это боевая конфигурация с автовыкаткой.

```yaml
# k8s/apps/lumen/values.yaml → controllers.main.containers.app.env
LUMEN_ADMIN_ROLES: homelab-admins          # п. 1
GITLAB_TOKEN:                              # токен с read_api, в extra/secrets.sops.yaml
  valueFrom:
    secretKeyRef: { name: lumen-env, key: GITLAB_TOKEN }
VAULTWARDEN_CLIENT_SECRET:                 # нужен, только если включена 2FA
  valueFrom:
    secretKeyRef: { name: lumen-env, key: VAULTWARDEN_CLIENT_SECRET }
```

**Доступ из пода.** В манифестах записано, что TLS к публичным адресам изнутри
кластера рвётся, поэтому к Keycloak под ходит через ClusterIP Traefik. К
Vaultwarden и GitLab будет то же самое. Есть два пути:

- добавить `vaultwarden.velessoft.org` и `gitlab.velessoft.org` в `hostAliases`:
  сертификат должен подойти внутреннему маршруту (уточнить, есть ли такой маршрут);
- указать в настройках внутренний адрес сервиса, например `http://<сервис>.<namespace>.svc:<порт>`,
  с «Разрешить HTTP» или «Разрешить приватные адреса». Трафик останется внутри кластера,
  если нет NetworkPolicy, которая его режет (уточнить).

## Архитектура кода

Модульный монолит оправдан: один процесс, один vault, команда небольшая.
Узкие места, которые появятся с ростом данных, но пока не болят:

| Что | Почему станет проблемой | Задача |
|---|---|---|
| Индекс в памяти, полная пересборка при старте | Время старта и память растут с vault | LUM-011 |
| Принадлежность к проекту считается на каждый запрос, O(заметок) | Заметно на тысячах файлов | LUM-011 |
| Типы API на клиенте пишутся вручную | Расхождение с сервером видно только при запуске | LUM-014 |
| Нет очереди с повторами для внешних записей | Блокирует запись в CalDAV и Nextcloud | LUM-013 |
| Обработчики без CSRF-токена, защита — только SameSite=Lax | Для текущих форм достаточно, для сетевого режима слабо | LUM-015 |

Следующий шаг по архитектуре — **LUM-015**: он закрывает пункты 3, 6 и 7.
