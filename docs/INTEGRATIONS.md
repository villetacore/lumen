# Интеграции

Интеграция забирает данные из внешней системы и раскладывает их по правилам
Lumen. Коннектор при этом ничего не знает про файлы: он только загружает и
приводит данные к общему виду, а запись в vault делает маппер в `internal/service`.

## Что уже работает

| Коннектор | Что даёт | Направление |
|---|---|---|
| **ICS** | Подписка на Google / Outlook / Яндекс календарь по секретной ссылке | ← |
| **CalDAV** | Nextcloud, Radicale, Baikal, Fastmail, iCloud | ← |
| **Nextcloud Notes** | Заметки из приложения Notes становятся заметками vault | ← |
| **GitHub / Gitea** | Issues и PR как задачи; тот же коннектор для Forgejo и GitHub Enterprise | ← |

Настраивается в веб-интерфейсе (раздел **Интеграции**) или прямо в
`.lumen/integrations.yaml`.

## Куда попадают данные

Это главное решение маппера:

| Тип элемента | Где оказывается | Почему |
|---|---|---|
| `event` | Только в индексе, на календаре | Рабочий календарь с тысячами встреч не должен засорять vault тысячами файлов |
| `task` | Заметка с чекбоксом в `70-integrations/<id>/` | Задачу хочется комментировать и связывать с другими заметками |
| `note` | Заметка там же | То же самое |

События интеграций переживают полную переиндексацию: они не выводятся из файлов,
и перезапрашивать их дорого.

## Идемпотентность и правки пользователя

Созданная заметка помечается плоскими ключами frontmatter:

```yaml
---
title: acme/repo#412 Починить парсер
tags: [github, bug]
source_connector: github
source_integration: work-issues
source_id: acme/repo#412
source_url: https://github.com/acme/repo/issues/412
source_hash: 9f2c1ab4
---
```

Правила обновления:

1. Хэш не изменился — файл не трогается вообще.
2. Хэш изменился — переписываются **только** `source_hash`, `source_url` и
   строка задачи (статус, срок). Всё, что вы дописали в заметку, остаётся.
3. Закрытие задачи снаружи ставит галочку в vault. Обратное направление
   (галочка в Lumen → закрытие issue) намеренно не реализовано: это уже запись
   во внешнюю систему, и она заслуживает отдельного явного действия.
4. Удаление интеграции убирает её события с календаря, но не трогает заметки —
   в них может быть ваш текст.

Ключи плоские, а не вложенный объект `source:`, потому что тогда их правит тот же
lossless-хелпер, что и любой другой скаляр ([ADR-0003](adr/0003-lossless-edits.md)).

## Секреты

Токены и пароли в конфигурации не хранятся. В полях типа `secret` указывается
ссылка: `bitwarden:github-token`, `keepass:db.kdbx#Работа/GitHub`,
`env:GITHUB_TOKEN`, `command:pass show work/gh`. Подробности —
[docs/SECRETS.md](SECRETS.md).

## Безопасность исходящих запросов

URL приходит от пользователя, поэтому HTTP-клиент коннекторов:

- ходит только по HTTP и HTTPS;
- **отказывается соединяться с непубличными адресами** — loopback, приватные
  сети, link-local (включая `169.254.169.254`), CGNAT. Проверка стоит на этапе
  соединения, поэтому публичное имя, которое резолвится в приватный адрес, тоже
  блокируется, как и редирект туда;
- для своего сервера в домашней сети есть явный флажок `allow_private`;
- ограничивает ответ 16 МБ, время — 60 секундами, редиректы — пятью.

## Расписание

У каждой интеграции свой интервал (по умолчанию 15 минут, минимум — минута).
Планировщик просыпается раз в 30 секунд и запускает то, что подошло по времени.
После ошибки интервал умножается на 4, к каждому запуску добавляется джиттер,
чтобы интеграции не стартовали одновременно.

ICS и CalDAV используют условные запросы (`ETag`, `If-Modified-Since`): ответ 304
не стоит почти ничего, и календарь можно опрашивать часто.

## Как добавить свой коннектор

```go
type Connector interface {
    Kind() string                  // "ics"
    Title() string                 // как показать в UI
    ConfigSchema() []ConfigField   // форма настроек
    Validate(Config) error
    Sync(context.Context, SyncInput) (SyncOutput, error)
}
```

`SyncInput` даёт конфигурацию, курсор с прошлого запуска, окно календаря,
HTTP-клиент с защитой выше и функцию разрешения секретов. Файлов коннектор не
видит. Новая интеграция — это один файл и строчка в `NewRegistry()`.

`SyncOutput.State` — произвольные строки: `ETag`, `since`, что угодно. Они
сохраняются в `.lumen/cache/integrations-state.json`, который не синхронизируется
между устройствами: чужой ETag хуже, чем никакого.

## Конфигурация

`.lumen/integrations.yaml` едет вместе с vault:

```yaml
integrations:
    - id: work-calendar
      kind: ics
      name: Рабочий календарь
      enabled: true
      interval: 15m0s
      values:
        url: https://calendar.google.com/calendar/ical/…/basic.ics
        calendar: Работа
    - id: work-issues
      kind: github
      name: Issues
      enabled: true
      interval: 30m0s
      folder: 20-projects/acme/issues
      values:
        repo: acme/repo
        token: bitwarden:github-token
        state: open
        assignee: alex
```

Идентификатор генерируется из названия и всегда остаётся латинским: он попадает
в URL, в имя папки и в ключи YAML на трёх платформах. Теги при этом сохраняют
исходный алфавит.

## Известные ограничения

- Многодневное событие «на весь день» показывается только в день начала.
- В RRULE поддержаны `FREQ`, `INTERVAL`, `COUNT`, `UNTIL`, `BYDAY`; `BYMONTHDAY`,
  `BYSETPOS` и переопределения через `RECURRENCE-ID` — нет.
- CalDAV только читает.
- Приглашения и статусы участников не разбираются.
