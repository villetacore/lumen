# ADR-0015. PostgreSQL и Redis как необязательные службы

**Статус:** принято · 2026-11-04 (запрос владельца). Уточняет
[ADR-0011](0011-operational-state.md) и [ADR-0006](0006-single-binary.md): один
бинарник без внешних служб остаётся рабочим вариантом.

## Контекст
Операционная БД — SQLite в каталоге на томе, привязанном к одному узлу, а её бэкап не
настроен. В кластере уже есть PostgreSQL с управлением через оператор. Сессии входа
живут в памяти, поэтому каждая выкатка завершает их у всех.

## Решение
Обе службы включаются переменными, по умолчанию всё как раньше:

| Переменная | Что меняет | Без неё |
|---|---|---|
| `LUMEN_DATABASE_URL` | Операционная БД в PostgreSQL | SQLite в `--state` |
| `LUMEN_REDIS_URL` | Сессии браузера в Redis | Сессии в памяти процесса |

**Что НЕ переезжает.** Заметки, задачи и тикеты остаются файлами Markdown (ADR-0001),
индекс — в памяти, пароли — в менеджере паролей. По-прежнему один процесс на один
vault: PostgreSQL не делает возможным второй экземпляр, потому что файлы vault общие.

**PostgreSQL.** Запросы пишутся один раз, с `?` и синтаксисом, понятным обоим движкам;
`state.DB` подставляет `$1`. Миграции — отдельные файлы `migrations_postgres/` с теми же
номерами и смыслом. Даты остаются строками RFC 3339: схемы совпадают почти дословно, а
перенос тривиален. Одно соединение для запросов даёт ту же гарантию, что SQLite:
чтение-правка-запись журнала и справочника не пересекаются. Второй `lumend` не запустится:
вместо блокировки каталога — advisory lock на отдельном соединении.

Перенос: `lumend state import <файл lumen.db>` в чистую базу, одной транзакцией, с
сохранением идентификатора экземпляра и номеров строк (запечатанные значения привязаны
к номерам, ADR-0011 §7). Обратного переноса нет: откат — прежний файл SQLite, который
импорт не меняет. Бэкап — `pg_dump`; команды `state backup/restore` в этом режиме
отказывают, а не делают вид, что сработали.

**Redis.** Только сессии: ключ — хеш значения cookie, значение — кто вошёл и срок, без
токенов Keycloak. Ни ключи, ни значения не дают войти. Память процесса остаётся первым
местом поиска, поэтому падение Redis не выбрасывает работающих пользователей, а только
мешает пережить следующий рестарт. Недоступный при старте Redis — предупреждение, а
не отказ запускаться.

## Последствия
**Плюсы.** Бэкап можно настроить средствами оператора PostgreSQL в кластере (проверить, что он
включён для новой базы), а данные не привязаны к тому Lumen. Выкатки не завершают сессии. Локальный запуск не усложнился.

**Минусы.** Два набора миграций нужно менять вместе: тест сверяет номера, смысл — на
совести автора. CI гоняет серверные тесты на обоих движках. Выход сессии не мгновенен при
падении Redis в момент выхода: запись может остаться до конца срока, но cookie удалён.

**Почему не заменить SQLite совсем.** Локальный режим и один бинарник — обещание проекта
(ADR-0006), а тесты на временном каталоге не требуют служб.
