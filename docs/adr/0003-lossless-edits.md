# ADR-0003. Точечная (lossless) запись в Markdown

**Статус:** принято · 2026-09-08

## Контекст
Изменение задачи через UI не должно переформатировать весь файл пользователя.
Наивный путь «распарсить → собрать заново» ломает форматирование, порядок ключей
frontmatter, комментарии и неизвестные поля.

## Решение
Запись всегда точечная:
- задача — заменяется **одна строка** файла;
- frontmatter — правится по ключу, с сохранением порядка и неизвестных полей;
- окончания строк, отступы, стиль маркеров и финальный перевод строки берутся из файла.

Парсер сохраняет для каждой сущности точные смещения (`line`, `byte range`),
чтобы можно было применить правку без пересборки документа.

## Последствия
**Плюсы:** vault остаётся «своим», diff в git читаемый, безопасно совмещать с Obsidian.
**Минусы:** парсер сложнее (нужны позиции), больше тестов.
**Проверка:** golden-тест «прочитать → записать без изменений → файл побайтово тот же»
для всех фикстур в `spec/testdata`.
