# ADR-0006. Один бинарник: сервер и интерфейс вместе

**Статус:** принято · 2026-09-08

## Контекст
Основной сценарий — личное локальное приложение. Заставлять человека запускать
отдельно Go-сервер и Node-процесс с фронтендом ради заметок — неоправданно.
При этом сетевой режим (сервер на домашнем NAS, клиенты на нескольких машинах)
терять не хочется.

## Решение
Собранный веб-клиент вшивается в бинарник через `go:embed`
(`server/internal/webui`). `lumend` отдаёт SPA на `/`, API на `/api/v1`, и этого
достаточно: `lumend --vault ./notes --open` — полноценное приложение.

Режимы не разделяются флагом «локальный/сетевой», они складываются из уже
существующих параметров:

| Сценарий | Команда |
|---|---|
| Локальное приложение | `lumend --vault ./notes --open` |
| Локально + шифрование | `LUMEN_PASSPHRASE=… lumend --vault ./notes --open` |
| Сервер для нескольких устройств | `lumend --addr 0.0.0.0:8787 --token …` |
| Только API (свой фронтенд) | `lumend --ui=false` |
| Разработка фронтенда | `lumend` + `npm run dev` с прокси на 5173 |

Статические файлы отдаются без токена (в них нет данных vault), всё под `/api`
токен требует.

## Последствия
**Плюсы:** одна команда для запуска, нечего разворачивать, версия UI и API
всегда совпадают, распространяется одним файлом.
**Минусы:** бинарник вырастает примерно на 300 КБ; UI нужно пересобирать перед
`go build` (это делает `make app` / `scripts/build.ps1`); в репозитории лежит
пустая директория `dist/` с `.gitkeep`, потому что `go:embed` требует непустую цель.
**Митигация:** без собранного UI сервер стартует и показывает страницу-заглушку
с инструкцией, а не падает.

## Замечание про десктоп
Flutter-клиент остаётся отдельным приложением: ему нужен офлайн-режим на
`lumen-core` без HTTP вообще ([ADR-0004](0004-two-parser-implementations.md)).
Вшитый веб-интерфейс его не заменяет и не мешает ему.
