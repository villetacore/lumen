# ADR-0007. Ссылки на секреты вместо самих секретов

**Статус:** принято · 2026-09-08

## Контекст
Нужны парольная фраза зашифрованного vault и токены интеграций. Варианты:

1. Хранить значения в конфиге, шифруя их мастер-ключом приложения.
2. Держать только в переменных окружения.
3. Хранить **ссылку** на секрет и доставать его из внешнего источника в момент
   использования.
4. Интегрироваться с системным хранилищем (DPAPI / Keychain / Secret Service).

## Решение
Вариант 3. Везде, где нужен секрет, конфигурация содержит строку вида
`scheme:value?params`: `env:`, `file:`, `command:`, `bitwarden:`, `keepass:`.
Значения параметров сами могут быть ссылками, с ограничением глубины вложенности.

Bitwarden и Vaultwarden читаются через официальный `bw` CLI, KeePass — через
`keepassxc-cli`.

## Последствия
**Плюсы**
- Конфигурацию (`.lumen/integrations.yaml`) можно класть в git и показывать на
  скриншотах: секретов в ней нет.
- Не нужен мастер-ключ приложения и его хранение — разблокировка остаётся за
  менеджером паролей, который ровно для этого и сделан.
- `command:` покрывает `pass`, `gopass`, `op`, `gpg` и любой свой скрипт без
  единой строчки кода в Lumen.
- Тестируется полностью: `Runner` подменяется, реальные менеджеры не нужны.

**Минусы**
- Нужен внешний бинарник; ошибки конфигурации проявляются в момент использования,
  а не при сохранении.
- `bw` требует активной сессии (`bw unlock --raw`), которая живёт до блокировки.
- Секрет проходит через stdout дочернего процесса.

## Почему не свой парсер KDBX
Формат KDBX4 — это Argon2d, ChaCha20/AES, HMAC-проверка блоков, сжатие и
внутренняя защита полей потоковым шифром. Сотни строк криптографического кода
ради задачи «прочитать одно поле», причём ошибка в них тихо ломает целостность
чужой базы паролей. `keepassxc-cli` уже установлен у каждого, кто пользуется
KeePassXC.

Пересмотреть стоит, если появится мобильный клиент: там запустить CLI нельзя,
и понадобится либо чтение KDBX внутри, либо системное хранилище.

## Отношение к ADR-0005
[ADR-0005](0005-encryption-at-rest.md) решает, *как* данные лежат на диске. Этот
ADR решает, *откуда берётся ключ*. Вместе они дают локальное зашифрованное
хранилище, которое открывается паролем из менеджера паролей и не требует ручного
ввода при старте службы.
