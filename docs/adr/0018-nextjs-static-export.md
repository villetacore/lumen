# ADR-0018. Веб-клиент на Next.js, статический экспорт

**Статус:** принято · 2026-11-04

## Контекст
Владелец попросил полностью перевести `web/` с Vite и React Router на Next.js.
При этом действует [ADR-0006](0006-single-binary.md): клиент вшит в `lumend`, образ
distroless без Node, отдельного процесса с фронтендом нет. Данные клиента приватные
и приходят из API после входа, поэтому серверный рендер почти ничего не даёт.

## Решение
App Router в режиме `output: "export"`. Сборка кладёт статику в `web/dist`, откуда её,
как и раньше, забирают `make app`, `scripts/build.ps1` и Dockerfile. Маршруты — файлы
в `web/src/app/`, навигация — `next/link` и `next/navigation`. `react-router-dom`
удалён, адреса не изменились.

Всё под `app/layout.tsx` рендерится только в браузере: оболочка `src/Shell.tsx`
подключена через `ssr: false`.

### Адреса с параметрами
Экспорт требует перечислить параметры при сборке, а `/tracker/:key`, `/issue/:key`,
`/task/:id`, `/view/:view` и `/note/*` заранее неизвестны. Поэтому каждый такой
маршрут собирается один раз с параметром-заглушкой `_` (`tracker/_/board.html`):

- `lumend` отдаёт эту страницу и её данные (`?_rsc`) на любой реальный адрес. Таблицы
  маршрутов в Go нет, он сопоставляет адрес с деревом файлов (`internal/webui`). Только
  catch-all `note` перечислен явно.
- `useParams` в браузере вернул бы `_`, поэтому параметры читаются из адреса:
  `useRouteParam` в `src/lib/navigation.tsx`.
- Неизвестный адрес теперь получает статус 404, а не 200.

### Защита черновиков
У Next нет аналога `useBlocker`. `src/lib/navigationGuard.ts` закрывает все пути:
ссылки (`onNavigate`), программные переходы (`useNavigate` из `lib/navigation`), «назад»
и «вперёд» (`popstate`), закрытие вкладки (`beforeunload`). Записи истории нумеруются,
иначе отказ от прыжка на несколько шагов нельзя отменить.

Next размонтирует страницу из своего обработчика `popstate`, поэтому защита должна
сработать раньше. Для этого `app/layout.tsx` вставляет inline-скрипт, который
регистрирует обработчик до загрузки скриптов Next.

Компоненты импортируют навигацию из `lib/navigation`, а не из `next/*` напрямую, иначе
переход минует защиту.

### Остальное
Каталог `src/pages` переименован в `src/screens`: имя занято Pages Router. Vite остаётся
dev-зависимостью как основа Vitest. Dev-сервер проксирует `/api`, `/auth`, `/healthz`
через `rewrites`, токен `make dev-prod` добавляет `src/proxy.dev.ts`, который
загружается только в `next dev` (расширение `dev.ts` есть в `pageExtensions` только
в этой фазе).

## Последствия
**Плюсы:** один бинарник, API и развёртывание не меняются, Node в рантайме не нужен;
код разбит по маршрутам.
**Минусы:**
- SSR, route handlers, server actions и `next/image` с оптимизацией недоступны.
- Заглушка `_` и обход порядка `popstate` опираются на поведение Next: при обновлении
  Next надо проверять глубокие ссылки, мягкие переходы и защиту черновика.
- Каждый первый переход на маршрут запрашивает файлы данных и чанк экрана. Ссылки не
  используют prefetch, чтобы длинные списки не порождали лишних запросов.

## Миграция
API и данные полностью совместимы, адреса прежние. `lumend` кэширует навсегда
`_next/static/` вместо `assets/`. Если понадобится SSR, это отдельное решение: оно
отменяет ADR-0006 и добавляет Node в образ и развёртывание.
