# ADR-0014. Vaultwarden: прямое чтение по API

**Статус:** принято · 2026-11-04. Уточняет [ADR-0009](0009-passwords-read-only.md),
не отменяет его: только чтение, только по запросу, ничего на диск.

## Контекст
Vaultwarden читался через `bw` CLI. В боевом образе (distroless) CLI нет, поэтому
раздел «Пароли» там не работал. Установка Node.js в образ ради одного CLI
расширила бы поверхность атаки и размер образа. Владелец просит получать всё по API.

Сервер Bitwarden/Vaultwarden хранит только шифротекст. Вход через Keycloak даёт
токен API, но **не ключ**: без мастер-пароля записи расшифровать нельзя.

## Решение
Бэкенд `vaultwarden` реализует клиентскую часть протокола на Go:

1. `POST /identity/accounts/prelogin` — параметры ключа (PBKDF2 или Argon2id).
2. Мастер-ключ выводится локально. На сервер уходит только `masterPasswordHash`,
   а при входе по API-ключу — вообще ничего, производного от пароля.
3. `POST /identity/connect/token` — пароль (`grant_type=password`) или API-ключ
   (`client_credentials`), который нужен учётным записям с двухфакторной защитой.
4. `GET /api/sync` — записи, папки, организации. Ключ учётной записи снимается
   мастер-ключом, ключи организаций — RSA-ключом учётной записи.

В памяти сессии лежат ключи и **зашифрованные** записи. Значение расшифровывается
в момент запроса одного поля; список содержит только названия, логины, адреса и
перечень полей. Коды 2FA считаются на сервере Lumen по RFC 6238.

Секрет API-ключа — ссылка по ADR-0007. Перенаправления не выполняются, чтобы хеш
и токен не ушли на чужой адрес. HTTP без TLS разрешён только для loopback или по
явной настройке.

`bitwarden` (CLI) остаётся для совместимости: у него свои настройки и сессия.

## Последствия
**Плюсы.** Работает в distroless без внешних программ. Все типы записей, папки,
организации, собственные ключи записей и пользовательские поля. Запись на сервер
невозможна: в коде нет ни одного запроса на изменение.

**Минусы.**
- Lumen знает протокол Bitwarden и должен следить за его изменениями: неизвестный
  формат даёт ошибку, а не неверные данные, потому что подпись проверяется до
  расшифровки.
- Ключи учётной записи находятся в памяти сервера, пока хранилище открыто. Go не
  гарантирует их затирание после закрытия. Защита — автозакрытие через 15 минут.
- Открытое хранилище общее для процесса: пока оно открыто, значения доступны любому
  администратору пространства, а не только открывшему (как и раньше, ADR-0009).
- Устаревшие форматы шифрования (типы 0, 1) и коды Steam Guard не поддерживаются.

**Почему не SSO Vaultwarden.** Keycloak подтверждает личность, но ключ всё равно
выводится из мастер-пароля. Передавать токен пользователя в Vaultwarden было бы
сложнее и ничего не дало бы для расшифровки.
