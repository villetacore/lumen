# ADR-0002. Пофайловая синхронизация вместо CRDT

**Статус:** принято · 2026-09-08

## Контекст
Нужна синхронизация между десктопом, вебом и сервером. Варианты: пофайловая
(версии + определение конфликта), трёхстороннее слияние, CRDT (Automerge/Yjs).

## Решение
MVP — пофайловая синхронизация: монотонная `revision` на файл, `sha256`,
optimistic concurrency (`If-Match`), конфликт → сохранение обеих версий.

## Последствия
**Плюсы:** реализуется за дни, легко отлаживать, файлы остаются обычными файлами,
нет служебных метаданных в vault.
**Минусы:** одновременная правка одного файла на двух устройствах даёт файл-дубль;
нет посимвольного слияния и совместного редактирования.
**Митигация:** debounce и агрессивный pull перед правкой; на M3 — `diff3` по
непересекающимся строкам; CRDT — отдельный слой, если появится командная работа.

## Замечание
Протокол `changes/push` спроектирован так, что переход на CRDT затрагивает только
применение дельт, но не форму API.
