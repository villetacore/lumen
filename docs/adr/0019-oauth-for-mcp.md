# ADR-0019. OAuth для подключения MCP-клиентов

**Статус:** принято · 2026-11-04. Уточняет §3 [ADR-0013](0013-mcp-server.md).

## Контекст
По ADR-0013 клиент подключается к `/mcp` с заголовком `Authorization`. Это
неудобно. Токен Keycloak быстро истекает. Статический токен даёт права
администратора от имени `token`: фильтр «мои тикеты» не находит ваших задач, а
предложение от `token` не подтвердить из своей учётной записи. Клиенты, которым
нельзя задать заголовок, например коннекторы Claude, подключиться не могут.

## Решение
1. **Lumen сам выступает сервером авторизации для `/mcp`** (OAuth 2.1, RFC 9728,
   8414, 7591). Включается вместе со входом через OIDC и операционной БД, без
   настройки Keycloak. Без OIDC `/oauth/*` отвечают 404, остаются прежние способы.
2. **Кто вошёл, решает Keycloak.** Клиента разрешает человек на экране
   `/connect/authorize` за обычным входом. Статический токен разрешить не может:
   за ним нет человека. Ответ принимается только с этого же сайта, экран нельзя
   встроить в чужую страницу.
3. **Клиенты регистрируются без входа**, только публичные, с обязательным PKCE
   S256. Адрес возврата: https, http на loopback (порт может меняться, RFC 8252)
   или схема из короткого списка (`cursor`, `vscode`, `vscode-insiders`). Имя
   клиента не проверяется, поэтому экран показывает и получателя ответа.
   Незавершённые регистрации удаляются через сутки, их не больше 1000.
4. **Токен открывает только `/mcp`**, REST API его не принимает. Токены непрозрачные
   (`lum_…`), в БД лежат только SHA-256 кодов и токенов.
5. **Права те же, что у человека.** Имя, группы и роль на каждый запрос берутся из
   справочника пользователей (LUM-066), который обновляется при входе. Поэтому
   работают `assignee: "me"` и подтверждение предложений.
6. **Сроки.** Код: 1 минута, один раз. Access: 1 час. Разрешение: 30 дней от
   выдачи, обновление токена его не продлевает. Refresh меняется при каждом
   обновлении; повтор старого в течение 30 секунд допускается (две сессии одного
   клиента, потерянный ответ), позже отзывает всё разрешение. Повтор кода тоже
   отзывает разрешение.
7. **Отключение.** Человек видит и отключает свои подключения на странице
   «AI-клиенты» (`/connect`); чужие для него не существуют.

## Последствия
**Плюсы:** подключение по одному URL, действия от своего имени, отзыв в один клик,
Keycloak не меняется.

**Минусы:**
- Lumen теперь хранит разрешения и отвечает за их безопасность.
- Человека, удалённого из Keycloak, Lumen не видит сразу: уже выданное разрешение
  работает до 30 дней, а роль и группы остаются такими, какими были при последнем
  входе. Отозвать чужое разрешение через интерфейс нельзя, только в БД.
- Разрешение нужно продлевать раз в 30 дней.

## Альтернативы
- **Keycloak как сервер авторизации.** Открытая динамическая регистрация клиентов в
  realm, общем с другими сервисами, и правки инфраструктуры. Отложено: аудитория
  токенов и политики регистрации требуют отдельной настройки.
- **Личные токены в настройках.** Проще, но токен копируют руками, и коннекторам
  Claude это не помогает. Можно добавить позже для клиентов без OAuth.
