# ADR-0009. Пароли: только чтение и только по запросу

**Статус:** принято · 2026-09-08

## Контекст
Нужно смотреть пароли из Bitwarden/Vaultwarden/KeePass внутри Lumen. Соблазн —
импортировать записи в vault как заметки: тогда работают поиск, ссылки и
синхронизация. Варианты:

1. Импортировать записи в vault.
2. Кэшировать список и значения в индексе.
3. Держать только список в памяти, значения запрашивать по одному.

## Решение
Вариант 3. Список записей живёт в памяти открытой сессии, значение достаётся
единственным эндпоинтом `POST /passwords/stores/{id}/reveal` — по одному полю
одной записи. Ни список, ни значения не попадают в vault, индекс, логи и на диск.

Мастер-пароль не хранится: он обменивается на непрозрачную сессию (токен `bw`
или пароль базы KeePass в памяти), которая закрывается сама через 15 минут.

## Последствия
**Плюсы**
- Пароль не может утечь в git, в бэкап vault или в полнотекстовый поиск.
- Потеря диска не раскрывает ничего сверх того, что уже защищено самим
  менеджером паролей.
- Модель понятна: Lumen — окно в чужое хранилище, а не второе хранилище.

**Минусы**
- Нет офлайна: закрыли хранилище — список пропал.
- Нет поиска по паролям вместе с заметками.
- Каждое раскрытие — вызов внешнего CLI, это десятки миллисекунд.

**Почему не (1)**
Заметка с паролем немедленно оказывается в индексе, в выдаче поиска, в git и в
каждой копии vault — включая незашифрованные. Один этот довод перевешивает все
удобства.

## Сопутствующие решения
- Мастер-пароль уходит во внешний CLI **через переменную окружения**: аргументы
  процесса видны всем пользователям машины.
- Ответ с значением — `POST` с `Cache-Control: no-store`, чтобы идентификатор
  записи не попал в URL, логи прокси и историю браузера.
- Раздел выключается, если сервер слушает сеть без всякой аутентификации.
