# Сборка, контейнер и выкатка

## Контейнер

[`Dockerfile`](../Dockerfile) собирает веб-клиент, вшивает его в `lumend` и
кладёт статический бинарник в distroless-образ (пользователь `nonroot`, 65532).

| Что | Значение в образе |
|---|---|
| Адрес | `LUMEN_ADDR=0.0.0.0:8787` |
| Vault | `LUMEN_VAULT=/vault` — том; пустой каталог станет новым vault |
| Проверка живости | `GET /healthz` — без авторизации |
| Версия | `--build-arg VERSION=…` → `lumend version` |

Остальные настройки — те же переменные `LUMEN_*`, что и у бинарника
([config.go](../server/internal/config/config.go)). Сервер в контейнере слушает
сеть, поэтому нужен `LUMEN_TOKEN` или OIDC ([AUTH.md](AUTH.md)).

В образе нет `bw` и `keepassxc-cli`: раздел «Пароли» и ссылки на секреты вида
`bitwarden:…` в контейнере не работают — секреты передаются через `env:`/`file:`.

### Kubernetes

Минимум — Deployment на одну реплику со стратегией `Recreate` (vault на томе
`ReadWriteOnce`, два экземпляра одновременно писать в одни файлы не должны),
PVC на `/vault`, Service на 8787 и Ingress. Для OIDC за внутренним CA Go читает
дополнительные корни из `SSL_CERT_DIR`.

## Открытый и приватный репозитории

Код открыт на GitHub. Выкатка — в приватной копии, которая отличается от
открытой ровно на один каталог с пайплайном:

```
GitHub  villetacore/lumen            исходники, открытый CI (проверки, сборка образа без публикации)
   │  синхронизация по расписанию (merge github/main → main)
   ▼
GitLab  приватная копия              + .gitlab-ci.yml: тесты → образ в Registry → MR с тегом
   │                                    в репозиторий инфраструктуры
   ▼
Argo CD                              выкатывает новый тег из репозитория инфраструктуры
```

Правила:

- Изменения кода — только в открытый репозиторий (PR → `main` на GitHub).
  Приватная копия получает их сама; руками туда пушится только пайплайн.
- Файлы приватной копии (`.gitlab-ci.yml`, `.gitlab/`, `deploy/`) в открытом
  репозитории запрещены — это проверяет задача `public-only` в
  [ci.yml](../.github/workflows/ci.yml).
- Из приватной копии в GitHub ничего не пушится: в её истории есть коммиты
  пайплайна, которых в открытой нет.

Почему не два remote в одном клоне с ручным push в оба: тогда пайплайн живёт
в той же истории, что и код, и рано или поздно уходит на GitHub. Одна ветка
наверху открытой истории и автоматический merge дают тот же результат без
ручной работы.
