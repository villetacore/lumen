# Сборка, контейнер и выкатка

Инструкции backup, восстановления и отката — в [OPERATIONS.md](OPERATIONS.md).
Первый локальный запуск — в [GETTING_STARTED.md](GETTING_STARTED.md).

## Разработка

```bash
make dev        # lumend :8787 + Next :5173 с hot-reload, vault — .dev-vault (копия vault-example)
make dev-prod   # только Next, /api проксируется на https://lumen.velessoft.org
make check      # те же проверки, что в открытом CI
```

`make dev-prod` показывает боевые данные, и правки в интерфейсе меняют боевой
vault. Вход — статический токен (`LUMEN_TOKEN` сервера, запасной путь рядом с
OIDC, [AUTH.md](AUTH.md)): переменная `LUMEN_TOKEN` или файл
`~/.config/lumen/token`. Dev-сервер Next сам добавляет `Authorization`, в браузер
токен не попадает. Другой сервер — `make dev-prod PROD_URL=https://…`.

Путь правки до боевого сервера: PR → `main` на GitHub → открытый CI публикует
`ghcr.io/villetacore/lumen:<sha12>` → зеркало в GitLab за ≤5 минут подхватывает
коммит и открывает MR с тегом в инфраструктуру → MR вливается сам после
зелёных проверок → Argo CD выкатывает.

## Контейнер

[`Dockerfile`](../Dockerfile) собирает веб-клиент, вшивает его в `lumend` и
кладёт статический бинарник в distroless-образ (пользователь `nonroot`, 65532).

| Что | Значение в образе |
|---|---|
| Адрес | `LUMEN_ADDR=0.0.0.0:8787` |
| Vault | `LUMEN_VAULT=/vault` — том; пустой каталог станет новым vault |
| Операционная БД | `LUMEN_STATE=/state` — отдельный постоянный том (ADR-0011); без него пользователи и история пропадут при пересоздании контейнера |
| Проверка живости | `GET /healthz` — без авторизации |
| Версия | `--build-arg VERSION=…` → `lumend version`, см. [Версии и релизы](#версии-и-релизы) |

Готовый образ — `ghcr.io/villetacore/lumen`, теги публикует задача `publish`
открытого CI:

| Тег образа | Откуда | Что значит |
|---|---|---|
| `<sha12>` (12 символов SHA) | каждый коммит в `main` | неизменный образ коммита; от него зависит выкатка |
| `main` | каждый коммит в `main` | последний коммит `main` |
| `X.Y.Z`, `X.Y.Z-rc.1` | git-тег версии | неизменный образ версии |
| `X.Y`, `X` | стабильная версия | самая новая версия этой ветки; `X` — начиная с `1.0.0` |
| `latest` | стабильная версия | самая новая стабильная версия |

Остальные настройки — те же переменные `LUMEN_*`, что и у бинарника
([config.go](../server/internal/config/config.go)). Сервер в контейнере слушает
сеть, поэтому нужен `LUMEN_TOKEN` или OIDC ([AUTH.md](AUTH.md)).

В образе нет `bw` и `keepassxc-cli`: типы хранилищ на их основе и ссылки на секреты
вида `bitwarden:…` в контейнере не работают, секреты передаются через `env:`/`file:`.
Vaultwarden по API ([PASSWORDS.md](PASSWORDS.md)) внешних программ не требует.

### Kubernetes

Минимум — Deployment на одну реплику со стратегией `Recreate` (vault на томе
`ReadWriteOnce`, два экземпляра одновременно писать в одни файлы не должны),
PVC на `/vault`, Service на 8787 и Ingress. Для OIDC за внутренним CA Go читает
дополнительные корни из `SSL_CERT_DIR`.

## Версии и релизы

Версии — [SemVer](https://semver.org/lang/ru/), источник истины — git-тег `vX.Y.Z`
на коммите `main`. Файлов с номером версии в репозитории нет: `version` в
`web/package.json` не используется, а `0.1.0-dev` в `lumend` — значение для сборки
без версии. До `1.0.0` совместимость может меняться в минорной версии; после —
несовместимое изменение API, формата vault или настроек требует новой старшей версии.

| Сборка | `lumend version` |
|---|---|
| Образ с тега `v1.2.3` | `lumend 1.2.3` |
| Образ с коммита `main` | `lumend <sha12>` |
| `make app`, `make build`, `make image` | из `git describe`: `lumend 1.2.3-4-gabcdef012`; без тегов — `0.1.0-dev` |
| `make app VERSION=…` | заданное значение |

Выпуск версии — обычный тег на коммите, который уже в `main`:

```bash
git switch main && git pull --ff-only
git tag -a v0.1.0 -m "v0.1.0"
git push origin v0.1.0
```

Дальше всё делает [ci.yml](../.github/workflows/ci.yml): те же проверки, что у
`main`, сборка с вшитой версией, проверка `lumend version`, публикация образа и
GitHub Release с заметками из PR. Предварительная версия — `v0.2.0-rc.1`: образ
только с точным тегом, релиз помечен как pre-release.

**Выкатка тегом не запускается.** Боевой сервер обновляется только сдвигом `main`
по тегу `<sha12>` (следующий раздел): зеркало переносит git-тег с `ci.skip`, а тег
образа в инфраструктуру не попадает. Поэтому на боевом сервере `lumend version`
показывает SHA, а не номер версии.

Что случается в особых случаях:

- **Сбой сети или реестра** — перезапустите упавшие задачи в Actions. Опубликованные
  образ и релиз повторный запуск не трогает.
- **Коммит вне `main` или тег не по формату** (`v1.2`, `v1.2.3+build`) — прогон
  падает, ничего не публикуется. Удалите тег и поставьте правильный.
- **Образ уже выпущен, а тег перенесён на другой коммит** — прогон падает, образ
  версии не заменяется. Выпустите следующую версию.
- **Патч к старой ветке** (`v1.2.4` после `v1.3.0`) — двигает только `1.2`; `1` и
  `latest` остаются на более новой версии.

## Открытый репозиторий и зеркало

Код открыт на GitHub. Выкатка — из закрытого зеркала, которое повторяет
открытый репозиторий один в один и своих коммитов не имеет:

```
GitHub  villetacore/lumen            исходники, открытый CI: проверки и образ ghcr.io/villetacore/lumen
   │  зеркалирование по расписанию (ветки и теги один в один)
   ▼
GitLab  зеркало                      пайплайн из репозитория инфраструктуры: ждёт образ
   │                                    и открывает MR с его тегом
   ▼
Argo CD                              выкатывает новый тег из репозитория инфраструктуры
```

Правила:

- Изменения кода — только в открытый репозиторий (PR → `main` на GitHub).
  Зеркало только для чтения: следующая синхронизация перезапишет то, что
  запушено туда руками.
- Конфиг пайплайна выкатки не лежит ни здесь, ни в зеркале — он в репозитории
  инфраструктуры и подключён в настройках проекта-зеркала. Файлы пайплайна
  (`.gitlab-ci.yml`, `.gitlab/`, `deploy/`) здесь по-прежнему запрещены —
  это проверяет задача `public-only` в [ci.yml](../.github/workflows/ci.yml).
