# MCP-сервер Lumen

Lumen отдаёт свои данные AI-клиентам (Claude Code, Claude Desktop, Cursor и
другим) по [Model Context Protocol](https://modelcontextprotocol.io). Решение и
границы — [ADR-0013](adr/0013-mcp-server.md).

- Адрес: `<адрес lumend>/mcp`, транспорт Streamable HTTP, без сессий.
- Версии протокола: 2024-11-05 … 2026-07-28 (согласуются с клиентом).
- Права те же, что в вебе: клиент видит и предлагает только то, что доступно
  вошедшему пользователю ([ADR-0012](adr/0012-access-policy.md)).

## Подключение

Нужен заголовок `Authorization: Bearer …` — токен Keycloak пользователя или
статический токен `--token`. Cookie браузера не подходят. В локальном режиме
без авторизации заголовок не нужен.

Claude Code:

```bash
claude mcp add --transport http lumen https://lumen.example.com/mcp --header "Authorization: Bearer $LUMEN_TOKEN"
```

Другие клиенты с поддержкой HTTP-транспорта — по той же схеме: URL `…/mcp` и
заголовок авторизации. Вход через OAuth прямо из клиента (dynamic client
registration) пока не поддерживается: токен Keycloak получают отдельно.

## Инструменты

Чтение (`readOnlyHint`):

| Инструмент | Что делает |
|---|---|
| `whoami` | Логин и роль в пространстве |
| `search` | Поиск по заметкам, документам и тикетам |
| `get_note` | Заметка или страница целиком |
| `list_projects` | Проекты трекера и их колонки |
| `list_issues` | Тикеты с фильтрами; `assignee: "me"` — назначенные вам |
| `get_issue` | Тикет: поля, описание, чек-лист, комментарии |
| `issue_history` | Кто и когда менял тикет |
| `list_sprints` | Спринты проекта |
| `get_proposal` | Состояние предложенного изменения |

Записи — только через подтверждение человеком:

| Инструмент | Что предлагает |
|---|---|
| `propose_create_issue` | Новый тикет |
| `propose_update_issue` | Изменить название, приоритет, исполнителя, метки, срок, спринт, описание |
| `propose_change_status` | Перевести тикет в другой статус (по правилам workflow) |
| `propose_comment` | Комментарий |

Инструмент `propose_*` ничего не меняет: он проверяет права и возвращает
`proposal_id`, точный предпросмотр и ссылку `confirm_at`. Изменение применяется,
когда **тот же пользователь** нажимает «Подтвердить» на странице
**«Подтверждения»** (`/approvals`). Модель и MCP-клиент подтвердить не могут.

- Предложение живёт 24 часа, применяется один раз.
- Если тикет изменился после предпросмотра (для правки полей — любое изменение
  файла, для статуса — другой статус), предложение становится `stale` и не
  применяется — попросите заново.
- Повтор вызова с тем же `request_id` возвращает то же предложение; с другими
  аргументами — ошибку.
- Применение идёт через те же сервисы с правами подтвердившего: автор
  комментария и тикета — он, уведомления и история — как при обычной работе.

## Что не доступно через MCP

Пароли, интеграции, участники проектов и администрирование. Удаление тикетов и
заметок. Запросы сервера к клиенту (sampling, elicitation) и уведомления — сервер
работает без сессий.
