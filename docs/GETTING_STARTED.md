# Начало работы

Lumen запускается как одно приложение: `lumend` обслуживает API и встроенный
веб-клиент. Для работы с собранным бинарником отдельный Node.js не требуется.

## Сборка из исходников

Нужны Git, Go 1.26, Node.js 24+ с npm и Make. Версии закреплены в
[go.mod](../server/go.mod), [package-lock.json](../web/package-lock.json)
и [CI](../.github/workflows/ci.yml).

```bash
git clone https://github.com/villetacore/lumen.git
cd lumen
npm ci --prefix web
make app
./dist/lumend --vault ./my-vault --open
```

Откройте http://127.0.0.1:8787. Если браузер не открылся автоматически,
перейдите по адресу вручную. `Ctrl+C` останавливает сервер.

### Сборка на Windows

В PowerShell из корня репозитория (Go и Node.js должны быть в PATH):

```powershell
npm ci --prefix web
./scripts/build.ps1
./dist/lumend.exe --vault ./my-vault --open
```

Это веб-приложение в локальном браузере. Отдельный Flutter-клиент имеет
[собственную инструкцию](../desktop/app/README.md).

## Выберите хранилище

`--vault` — папка с Markdown-файлами. Новая папка создаётся с каталогами входящих,
заметок, проектов и дневных записей. Для знакомства можно скопировать
`vault-example` в отдельную папку и запустить Lumen с этой копией.

Существующий vault Obsidian можно подключить тем же флагом. Перед первым
подключением сделайте резервную копию: изменение задачи в Lumen меняет исходный
файл. Расширения и плагины Obsidian не становятся функциями Lumen автоматически.

Не запускайте два процесса Lumen на одном vault. Собственную папку с данными
держите вне checkout исходников, чтобы случайно не включить её в коммит.

## Первые пять минут

1. Откройте «Сегодня» и введите `Подготовить макет !A @завтра` в строке добавления.
2. Найдите задачу в «Все задачи», откройте карточку и добавьте описание.
3. Нажмите `+` рядом с «Проекты», создайте проект с описанием.
4. В проекте добавьте документ или рабочую запись через раздел материалов.
5. Откройте файл в своём редакторе: данные остаются обычным Markdown.

Подробности и сочетания клавиш — в [руководстве пользователя](USER_GUIDE.md).

## Запуск в контейнере

```bash
docker run -d --name lumen \
  -p 127.0.0.1:8787:8787 \
  -v lumen-vault:/vault \
  ghcr.io/villetacore/lumen:main
```

Остановка: `docker stop lumen`. Повторный запуск: `docker start lumen`.
Данные остаются в именованном томе `lumen-vault`.

Для сетевого доступа нужны [настройка авторизации](AUTH.md), HTTPS и резервные
копии. В контейнере по умолчанию сервер слушает `0.0.0.0`, а без настроенного
токена/OIDC API открыт. Привязка порта к `127.0.0.1` в примере ограничивает
доступ машиной, на которой запущен Docker.
